# Next.js Framework Patterns & Best Practices Documentation

## Overview

This comprehensive documentation establishes the project-specific development patterns, architectural conventions, and best practices for Next.js applications within the AI Agency project. It covers the actual implementation patterns observed in the `apps/docs` application, which serves as the reference implementation.

The documentation is structured to provide practical guidance extracted from real-world implementation, focusing on modern Next.js 15+ features alongside proven development workflows.

---

## 1. Next.js Framework Fundamentals

### Core Application Architecture

#### Application Structure
```
apps/docs/
├── app/                          # App Router Directory
│   ├── layout.tsx               # Root layout (server component)
│   ├── page.tsx                 # Home page (server component)
│   ├── globals.css              # Global styles
│   ├── favicon.ico              # Favicon
│   └── fonts/                   # Font files
│       ├── GeistVF.woff         # Geist Sans variable font
│       └── GeistMonoVF.woff     # Geist Mono variable font
├── package.json                 # Dependencies & scripts
├── next.config.js              # Next.js configuration
└── tsconfig.json               # TypeScript configuration
```

#### Key Architectural Decisions

1. **App Router Implementation**: Modern file-based routing system
2. **Server-First Components**: Default to Server Components for optimal performance
3. **TypeScript Integration**: Strict type safety throughout the application
4. **Monorepo Architecture**: Shared packages via workspace dependencies
5. **Modern Font Management**: Variable fonts for optimal performance

### Configuration Patterns

#### Package.json Structure
```json
{
  "name": "@aigency/docs",
  "version": "0.1.0",
  "type": "module",
  "private": true,
  "scripts": {
    "dev": "next dev --turbopack --port 3001",
    "build": "next build",
    "start": "next start",
    "lint": "next lint --max-warnings 0",
    "check-types": "tsc --noEmit"
  }
}
```

**Key Configuration Notes:**
- `--turbopack` for enhanced development performance
- Custom port allocation avoids conflicts in monorepo
- Strict linting with zero warnings tolerance
- Type checking as separate script for CI/CD integration

#### Next.js Configuration (next.config.js)
```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {};

export default nextConfig;
```

**Pattern Note:** Implementation follows minimal configuration philosophy, leveraging Next.js 15+ defaults.

#### TypeScript Integration (tsconfig.json)
```json
{
  "extends": "@repo/typescript-config/nextjs.json",
  "compilerOptions": {
    "plugins": [{ "name": "next" }]
  }
}
```

**Best Practice:** Centralized TypeScript configuration via monorepo workspace.

## 2. React Component Organization Patterns

### Component Architecture Strategy

#### Server vs Client Component Patterns

**Server Components (Default):**
```tsx
// layout.tsx - Server Component Pattern
import React from 'react';
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

interface RootLayoutProps {
  children: React.ReactNode;
}

export default function RootLayout({ children }: RootLayoutProps) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

**Key Server Component Patterns:**
- Automatic metadata export for SEO optimization
- TypeScript interfaces for prop validation
- No client-side JavaScript overhead
- Default pattern throughout application

#### Client Component Integration
```tsx
// page.tsx - Client Component with Theme Pattern
'use client';

import React, { useState } from 'react';
import { Button } from "@repo/ui/button";

export default function Home() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <div>
      <Button
        onClick={() => setIsOpen(true)}
        appName="docs"
        className="secondary"
      >
        Open alert
      </Button>
    </div>
  );
}
```

**Client Component Usage Guidelines:**
1. **'use client' Designation**: Explicit client-side marker
2. **Minimal Client Boundaries**: Keep client components small and focused
3. **Prop Interfaces**: Consistent TypeScript validation
4. **Hydration Awareness**: Design for smooth client/server hydration

### Component Composition Strategy

#### Theme Image Component Pattern
```tsx
type Props = Omit<ImageProps, "src"> & {
  srcLight: string;
  srcDark: string;
};

const ThemeImage = (props: Props) => {
  const { srcLight, srcDark, ...rest } = props;

  return (
    <>
      <Image {...rest} src={srcLight} className="imgLight" />
      <Image {...rest} src={srcDark} className="imgDark" />
    </>
  );
};
```

**Pattern Benefits:**
- Type-safe prop extension with Omit utility
- Light/dark theme support with CSS classes
- Reusable across multiple contexts

#### Component Organization Guidelines

1. **File Naming**: PascalCase for components
2. **Directory Structure**: Feature-based organization
3. **Prop Interfaces**: Dedicated interface definitions
4. **Type Safety**: Strict TypeScript types throughout
5. **Styling**: CSS modules or utility-first approach

### Advanced Component Patterns

#### Conditional Rendering with CSS Classes
```tsx
<div data-oid={generateUniqueId()}>
  {/* Conditional rendering patterns */}
</div>
```

**Pattern Note:** Unique identifier generation for debugging

#### Performance-Optimized Font Loading
```tsx

<body className={`${geistSans.variable} ${geistMono.variable}`}>
```

## 3. Data Fetching and Server State Management

### Server-Side Data Fetching Patterns

#### Server Component Data Fetching
```tsx
// Server Component Pattern
async function getUserData(userId: string) {
  // Database or API call
  const data = await fetchUserData(userId);
  return data;
}

export default async function UserProfile({ params }) {
  const user = await getUserData(params.id);

  return (
    <div>
      <h1>{user.name}</h1>
    </div>
  );
}
```

**Server Data Fetching Guidelines:**
1. **Server Components First**: Default to server-side data fetching
2. **Request Memoization**: Automatic deduplication of identical requests
3. **Streaming**: Automatic streaming for dynamic content
4. **Error Boundaries**: Proper error handling for failed requests

### API Route Handler Patterns

#### Route Handler Implementation
```tsx
// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const query = searchParams.get('q');

  return NextResponse.json({ users: [], query });
}

export async function POST(request: NextRequest) {
  const body = await request.json();

  return NextResponse.json(
    { message: 'User created', data: body },
    { status: 201 }
  );
}
```

**Route Handler Best Practices:**
1. **Endpoint Organization**: RESTful resource-based routing
2. **HTTP Method Support**: Multiple methods per route
3. **Request Parsing**: Type-safe request handling
4. **Response Standardization**: Consistent response format

#### Server Actions Implementation
```tsx
// Server Action Pattern (Next.js 13+)
'use server';

export async function createUser(formData: FormData) {
  const name = formData.get('name');

  // Server-side processing
  await createUserInDatabase({ name });

  revalidatePath('/users');
  return { success: true };
}
```

**Server Action Guidelines:**
1. **'use server' Directive**: Explicit server action marking
2. **File Location**: Either at root of server component files or in route handlers
3. **Form Integration**: Seamless form submission handling
4. **Cache Revalidation**: Automatic cache management

### State Management Strategy

#### React 19+ State Management
```tsx
'use client';

import { useState, useOptimistic, useTransition } from 'react';

export function CommentForm({ onSubmit }) {
  const [isPending, startTransition] = useTransition();
  const [optimisticComments, addOptimisticComment] = useOptimistic([]);

  const handleSubmit = (formData) => {
    startTransition(async () => {
      addOptimisticComment(formData);
      await onSubmit(formData);
    });
  };

  return (
    <form action={handleSubmit}>
      <input name="comment" disabled={isPending} />
      <button type="submit" disabled={isPending}>
        {isPending ? 'Submitting...' : 'Submit'}
      </button>
    </form>
  );
}
```

**Modern State Management Patterns:**
1. **useOptimistic**: Optimistic UI updates
2. **useTransition**: Non-blocking state updates
3. **Server Actions**: Form integration with server state
4. **Suspense**: Progressive loading boundaries
